## Objective

## Does the Index Auto-Update When You Add a Page?

**Yes — after the new page is _published_, and if its path falls inside the index's `include:` glob.** Automatic, not instantaneous, not triggered by merely authoring.

- Generated by the pipeline from `helix-query.yaml`. Preview/publish of a matching page reindexes it — no manual JSON editing.
- Trigger = publish (or preview), not save/author.
- Incremental and slightly delayed (seconds to a couple of minutes).
- Path must match `/us/en/newsroom/press-releases/**` or it won't be picked up.
- Backfill: the 39 already-migrated pages need a one-time (re)publish/bulk index to populate; new pages after that are automatic.
- Unpublish removes the row on the next reindex.

## Why Have This — Benefits

- **Data source for a press-release listing page** — publish a release, it appears in the list with no manual edit.
- **Sorting/filtering for free** — `articleDate` (newest-first) and `eyebrow` (category) client-side.
- **Pagination / "load more"** — flat sheet (`total`/`offset`/`limit`/`data[]`).
- **Powers search, feeds, related-content** from one endpoint.
- **Decouples content from presentation** — authors publish as normal; index self-updates.
- **Cheap and fast** — static JSON on the CDN, no database.

**When _not_ worth it:** if nothing will ever consume it (pages reached only by direct link).

## Planned `helix-query.yaml` (to be written in Execute mode)

```yaml
version: 1

indices:
  # --- existing index (unchanged) ---
  pages:
    include:
      - '/**'
    exclude:
      - '/**.json'
    target: /query-index.json
    properties:
      lastModified:
        select: none
        value: parseTimestamp(headers["last-modified"], "ddd, DD MMM YYYY hh:mm:ss GMT")
      robots:
        select: head > meta[name="robots"]
        value: attribute(el, "content")

  # --- new: press-releases listing index ---
  press-releases:
    include:
      - '/us/en/newsroom/press-releases/**'
    exclude:
      - '/**.json'
      - '/us/en/newsroom/press-releases/query-index.json'
    target: /us/en/newsroom/press-releases/query-index.json
    properties:
      title:
        select: head > meta[property="og:title"]
        value: attribute(el, "content")
      description:
        select: head > meta[name="description"]
        value: attribute(el, "content")
      image:
        select: head > meta[property="og:image"]
        value: attribute(el, "content")
      articleDate:
        select: main .article-header [data-field="articleDate"]
        value: textContent(el)
      eyebrow:
        select: main .article-header [data-field="eyebrow"]
        value: textContent(el)
      lastModified:
        select: none
        value: parseTimestamp(headers["last-modified"], "ddd, DD MMM YYYY hh:mm:ss GMT")
      robots:
        select: head > meta[name="robots"]
        value: attribute(el, "content")
```

> During execution I'll inspect the **rendered** `article-header` DOM (block JS output) and pin the `articleDate`/`eyebrow` selectors to real elements. If those values aren't exposed as discrete DOM nodes, I'll switch them to metadata-derived selectors (or drop to core fields) rather than ship selectors that resolve empty.
