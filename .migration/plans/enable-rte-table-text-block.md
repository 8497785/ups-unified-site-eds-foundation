## Answer: Yes, it's possible — via component-filter `rte` config
The Adobe doc confirms the RTE toolbar is configurable. Contrary to what I concluded earlier (I was looking at the component-*model* field spec, which has no table toggle), table support is enabled through a **component filter** carrying an **`rte`** property — not through the richtext model field. So this is a real, supported config path, not a dead end.

Per the doc:
- RTE config lives "as part of a component filter with the property `rte`."
- Enable the table button via `rte.toolbar.insert` containing `"table"`.
- Configure behavior via `rte.actions.table` (e.g. `wrapInParagraphs`, `label`, `shortcut`).
- All features the backend supports are active by default; you deactivate what you don't want. **Caveat:** "Activating options that are not compatible with your project type is not supported" — so xwalk/Edge Delivery must actually support the table plugin for this to render. This is the one risk to validate live.
